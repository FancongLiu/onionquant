# 技术选型决策框架

## 五关检查

1. **社区验证**: GitHub stars <1K=小众, 1K-10K=中等, 10K+=主流。最近commit？Issue活跃？
2. **企业采用**: 有没有知名公司在用？有没有生产案例blog？是不是大厂出品？
3. **面试可聊**: 能讲清楚架构原理吗？面试官可能听说过吗？
4. **规模匹配**: 单人项目需要企业级方案吗？简单方案够不够？
5. **官方>社区**: 官方SDK优先，社区方案必须有足够stars+企业案例+活跃维护

## 反面案例 (2026-06-13)

claudemux: stars极少，非官方，面试无法解释，企业不用。
教训: 听起来匹配≠该选。先查stars和官方替代品。

## 快速矩阵

| 主流 | 10K+ stars 或大厂官方 或3+企业案例 |
| 可面试 | 能讲清原理+为什么不用替代方案 |
| 匹配 | 简单方案能解决的，别引入复杂依赖 |
